# 故障排查

[简体中文](troubleshooting.md) · [English](en/troubleshooting.md)

## 摘要失败时会发生什么

插件先按设置重试。默认首次请求之后再尝试 2 次，检查失败会把问题反馈给摘要模型。

尝试次数耗尽后，对话显示失败原因和诊断位置。尚未提交的原始上下文继续保留；分页流程中已经完成的页面会保存为恢复进度。

| 提示类型 | 处理方式 |
| --- | --- |
| 摘要超时或断流 | 检查供应商连接，在设置页调整等待时间与重试次数 |
| 摘要结构不完整或输出不足 | 提高摘要输出上限，或选择更适合长文摘要的模型 |
| 要求或进度检查失败 | 使用诊断中的拒绝原因定位问题；重试会携带对应反馈 |
| 输入或单个工具组过大 | 查看请求容量信息，调整摘要模型及输入预算 |
| 连续失败达到阈值 | 查看最近诊断，解决原因后通过 `/compact` 再次尝试 |
| 恢复尚未完成 | 保留事务记录和备份，重启后读取恢复结果与诊断 |

## 诊断文件

默认存储目录：

```text
<DSH_HOME>/storages/dsh-compaction-weave/
```

- `diagnostics/`：失败阶段、错误码、尝试次数、耗时、用量和分页进度。
- `sessions/`：按会话组织的历史原文与附件。
- `audit-reject/`：未通过要求或进度检查的候选摘要材料。
- `summary-config.json`：摘要模型与重试设置。

对话中的路径对应这一次操作，排查时优先使用该文件。常规诊断采用允许字段列表记录元数据；审计拒绝材料可能包含原文和候选摘要片段，分享前检查其中的任务内容。

## 提交 Issue

报错、回答质量下降（“降智”）、压缩后忘记要求或工作进度，都可以 [提交 Issue](https://github.com/NightFrost42/dsh-compaction-weave/issues/new/choose)。选择中文或英文模板，填写版本、使用的模型、复现步骤和预期／实际表现。

报错时附上对话提示对应的诊断文件；回答质量或记忆问题附上关键要求，以及压缩前后表现不同的对话片段。日志和片段中的密钥、私人信息请先移除。

## 更新与卸载

在 DSH 插件管理页更新或卸载插件。命令行 profile 可使用：

```bash
dsh plugin --profile web add /absolute/path/dsh-compaction-weave-0.3.2-rc.1.tgz
dsh plugin --profile web remove dsh-compaction-weave
```

完成后重启 DSH。归档与设置位于独立存储目录，包更新会继续使用这些文件。
